# Classflow - Cloud Classroom Platform

## ปัญหาและผู้ใช้

ครูต้องรวมการบ้านจากหลายที่ ตรวจไฟล์และกรอกคะแนนหลายรอบ เมื่อต้องเปลี่ยนเกณฑ์เกรดหรือใช้ Excel มักเกิดรหัสนักเรียนไม่ตรงและบันทึกข้อมูลไม่ครบ นักเรียนติดตามกำหนดส่ง คะแนน และข้อเสนอแนะได้ยาก

กลุ่มเป้าหมาย: ห้องเรียนหรือรายวิชาในมหาวิทยาลัย ขนาดสาธิต 1–3 ห้อง ผู้ใช้หลักคือครูและนักเรียน ระบบจัดข้อมูลตามห้องเรียนและสมาชิก

## เป้าหมาย

รวมงาน เนื้อหา คะแนนและการสื่อสารไว้ด้วยกัน ลดการกรอกคะแนนซ้ำ ตรวจข้อมูลก่อนนำเข้า ให้ครูทดลองเกณฑ์โดยเห็นผลก่อนเผยแพร่ นักเรียนเห็นเฉพาะคะแนนและไฟล์ส่วนตัว

## ขอบเขต

In-Scope: ห้องเรียนและรหัสเข้าร่วม, บทบาทครู/นักเรียน, โพสต์เนื้อหา/งาน, ส่งไฟล์, คอมเมนต์, แชตส่วนตัว, ตรวจงานด้วย Rubric, คะแนนสอบ, เกรดอิงเกณฑ์และ Z-score, Dashboard, Excel import/export, Timeline และสัญญาณช่วยติดตามนักเรียน

Out-of-Scope: ประชุมวิดีโอ, ระบบสอบออนไลน์เต็มรูปแบบ, ตรวจการบ้านด้วย AI, แก้ Word/Excel ใน browser, จ่ายเงิน, เชื่อมระบบทะเบียน และระบบใช้งานระดับมหาวิทยาลัยโดยไม่มีการทดสอบโหลดเพิ่มเติม

## Milestones

| ระยะ | ผลลัพธ์ | เกณฑ์ตรวจ |
|---|---|---|
| 1: ออกแบบ | ขอบเขต, permission matrix, schema, architecture | ตรง rubric และไม่เพิ่มบริการที่ไม่ได้ใช้ |
| 2: Core | ห้องเรียน โพสต์ ส่งไฟล์ ตรวจงาน แชต | สองบัญชีนักเรียนแยกข้อมูลกัน |
| 3: Grading | เกรด Dashboard Excel Rubric Timeline | ตรวจกรณีขอบ, SD=0, import ทั้งชุด |
| 4: Deployment | CloudFormation, HTTPS, Cognito, private S3 | สาธิตบน AWS ด้วยบัญชีจริง |
| 5: Presentation | demo script, trade-offs, evidence, costs | ตรวจบริการ What/Role/Why และ Q&A |

## ความปลอดภัยและงบ

ใช้ Cognito ยืนยันตัวตนและกลุ่ม teachers ที่ผู้ดูแล AWS กำหนดเอง ตรวจสิทธิ์สมาชิกใน backend ทุกคำขอ S3 Block Public Access สำหรับทั้งสอง bucket ไฟล์งานเข้าถึงด้วยลิงก์หมดอายุหลังตรวจสิทธิ์ คะแนนและข้อมูลธุรกรรมอยู่ DynamoDB

ใช้ Lambda on demand, DynamoDB on demand และ S3 แชต poll เฉพาะเมื่อเปิดหน้า ไม่ตั้ง scheduled job สำหรับกำหนดส่ง ใช้ CloudFront สำหรับ HTTPS และ cache static assets ตั้ง log retention 7 วัน ตรวจเครดิตก่อน deploy และตั้ง Budget alert ตามบัญชีจริง ไม่ถือเครดิต $100 ในอดีตเป็นยอดปัจจุบัน
